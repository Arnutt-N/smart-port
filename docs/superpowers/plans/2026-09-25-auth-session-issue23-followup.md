## Summary

Bring in-repo API clients onto D3 cookie authentication, align password entry pages with the existing backend policy, implement the confirmed remember-me TTLs, and keep multiplier Issue #23 open until HR supplies signed-off expected values.

## Confirmed decisions

1. **Remember-me off:** session cookies; server absolute expiry is 12 hours after login.
2. **Remember-me on:** persistent cookies; server absolute expiry is 30 days after login.
3. Refresh rotation keeps the original session expiry. It never extends either cap.
4. Access JWTs remain at most one hour, and their expiry is also bounded by the session expiry. A token is valid only while `now < exp` and `now < session_exp`: exact-second expiry already counts as expired for both claims.
5. The D6 schema rollout revokes existing refresh sessions because current rows do not record whether remember-me was selected or the start of the original session. JWTs without the new session-expiry claim are rejected. Users must log in again after this release and select the desired setting. Migration-revoked legacy refresh cookies return 401 and are cleared without revoking a user's new post-cutover sessions; replay of a token revoked by normal refresh rotation keeps the existing replay response. All authenticated API traffic stays paused from the pre-cutover drain until the new backend is verified healthy, so no pre-D6 access JWT can reach a protected route on the old validator during the interval; after cutover, neither legacy refresh cookies nor pre-D6 access JWTs authenticate.
6. Existing backend password policy remains authoritative: at least 12 Unicode code points, one upper-case letter, one lower-case letter, one number, one special character, at most 72 UTF-8 bytes, and no reuse of the last five passwords.
7. The current multiplier runtime calculates with the matched area's ratio and a 365-day year/30-day month. The offline validator and older pack still use fixed 200%/360 days; those are known drift, not approved HR policy. Align the local validator to the current runtime contract for technical checks, but hold HR acceptance until HR/Product explicitly confirms the ratio, year basis, rounding, and inclusive-date rules against the independently prepared workbook. If they reject the runtime contract, stop T7 acceptance and create an approved calculation-change plan; do not rewrite HR expectations or silently change backend policy in this follow-up.
8. The UAT case CSV has no `basis_type` field. For local technical checks, select a master area with the same deterministic rule in offline validation and live UAT: match normalized location and overlapping dates, prefer `EMERGENCY_DECREE` for service starts on/after `2005-01-01` and other basis types before that date, fall back to the available group, and fail closed if the winning priority group has more than one row. Exact staging-master parity runs before live selection. HR/Product must confirm this area-selection rule against the independently prepared workbook before HR acceptance; a differing rule is a separate domain-change decision.

The case CSV has no `basis_type`; both consumers use `selectMultiplierArea()` on their respective parity-equivalent area sets, so offline validation never queries staging and never invents a case type. The live runner also compares every master/API `basis_type` during exact-set parity before selection. Preserve internal whitespace, punctuation, and case in legal/source references so substantive differences remain visible. Dates must be canonical `YYYY-MM-DD`; blank/NULL end dates normalize to empty.
- Define a canonical identity as the JSON-encoded tuple `[province, database_district_key, basis_type, effective_start_date]`, matching `uq_area_multiplier_exact_period` at `database/13-multiplier-time-counting.sql:41-43`. Normalize a NULL/blank district to empty first, then map empty district to the schema's generated-column sentinel `__ALL__` for `database_district_key`. Reject duplicate identities independently in the HR master and staging set. Compare `effective_end_date`, `multiplier_ratio`, `legal_reference`, and `source_reference` as values for each identity; they are not part of the identity key. For `multiplier_ratio`, take decimal text from CSV or a finite JSON number from the staging API (whose decorator casts it to float); for the number use its canonical base-10 `String(value)` form, reject exponent notation and more than two fractional digits, range-check 100.00–999.99, and convert digits to integer hundredths without floating-point arithmetic. Thus CSV `100.00` and JSON number `100` are equivalent; `100.01` is different. A representation outside this exact contract fails closed rather than being rounded or compared with an epsilon.
- Match the full active row sets by canonical identity, then compare the complete normalized row values before any `POST /multiplier`. Any malformed CSV, duplicate, missing/extra identity, or compared-field mismatch is a hard stop. Emit only the generic failure category and aggregate counts.
- Parse and validate every UAT row before network activity. Keep `case_id` opaque; require a unique nonblank normalized ID and all required case fields, reject invalid rows rather than filtering them, and require at least ten accepted HR cases. In the live runner, successful completion requires parsed=accepted=executed=passed, with failed=skipped=0; a cleanup failure is a failed case. The offline validator also requires accepted=parsed and at least ten cases for HR inputs, so its 12/12 result cannot hide malformed or discarded rows. Emit only aggregate counts and generic categories, never IDs.
- For technical expected-value checking, the offline validator uses the shared selector's chosen master row ratio and reproduces the inspected runtime's 365-day/30-day breakdown and floor-before-breakdown rule. The independent HR Excel values remain immutable acceptance inputs. HR/Product confirmation of both calculation and area-selection contracts is a separate gate; a technical 12/12 result alone does not satisfy it.
- Tests must send converter-generated CSVs containing a legal/source reference with a comma, doubled quote, and embedded newline through both consumers and prove the decoded references remain exact. Also cover BOM and both line endings, malformed CSV sentinel privacy, blank/NULL open-end conversion and parity with API `null`, `TODO` rejection, duplicate identity, equivalent CSV/JSON ratio encodings, a true ratio mismatch, non-200% calculations, 360/365-day and fractional-effective-day boundaries, zero/duplicate/mixed/invalid/insufficient case IDs, accepted/executed count equality, and the shared selector's emergency/non-emergency priority and tie failure. CSV/path/case input failures stop before login or POST; API-dependent parity/selection failures stop before POST after the required login/fetch.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Existing sessions do not record remember choice or original session age | Migration 36 revokes active refresh rows; new JWT claim rejects old access JWTs; announce sign-in again. |
| Access JWT lives past refresh expiry | Include session_exp in signed JWT; bound exp at issuance; validate both claims on every request with strict `now < claim` validity (exact-second expiry is expired). |
| Cookie path or browser same-site policy blocks refresh | Use canonical /api/auth paths; test path scoping; keep browser clients same-site or behind a same-site proxy. |
| Rotation silently extends a session | Carry the original database expires_at through every rotation and assert exact equality in integration tests. |
| Migration not present on production bootstrap | Update ordered migration, tidb-init, Compose mount, CI mount, and migration baseline; parity gate must pass before deployment. |
| Baseline update falsely assumes production migration ran | Inspect actual schema first; apply DDL/revocation manually under the approved release window, verify, then record the migration marker before backend deploy. |
| Render runner silently baselines the new production migration | Verify live build/root-dir/runtime state; apply migration 36 via approved admin path before deployment and confirm its schema_migrations marker plus DDL effects. |
| Script logs expose credentials | Test and review output contains only status/error categories; never serialize request body or cookie headers. |
| HR-derived UAT details leak through console output | Exercise actual validator and live-UAT output paths with synthetic sentinels; allowlist aggregate output only and never log row/value/response/path details. |
| Staging still has TEST_SEED or stale master rows when private HR cases are run | Require authorized staging reconciliation and exact active-row parity against the approved private master before any UAT write; mismatch or missing evidence hard-stops T7. |
| The 200%/360-day offline oracle conflicts with the current per-area/365-day backend and possibly HR Excel | Align local technical checks to the inspected backend with boundary tests; require an independent written HR/Product rule decision before acceptance. If it differs, stop T7 and obtain a separate approved calculation-change plan. |
| Live UAT silently filters approved cases or succeeds with zero executed | Reject malformed/duplicate/incomplete input before network use, never filter by case-ID prefix, require at least ten HR cases and parsed=accepted=executed=passed with zero failures/skips; test the actual CLI. |
| Offline validator and live runner choose different basis types for overlapping periods | Use the same order-independent `selectMultiplierArea()` on approved master versus parity-verified staging rows; no `basis_type` case field is assumed, top-priority ties fail closed, and HR/Product confirms the priority before acceptance. |
| Existing synthetic-only validator regression is lost while changing its CLI output | Keep `scripts/tests/validate-multiplier-phase0.test.mjs` in the file inventory and Node gate; preserve no-seed/no-director assertions. |
| XLSX sync overwrites tracked templates or publishes HR data | Require explicit external workbook/output paths, reject repository-resolved paths and overwrite, keep `openpyxl` in an isolated requirements file, and verify tracked templates remain unchanged. |
| Existing local/staging DB silently skips migration 36 after baseline seeding | Preflight the column and migration marker before test/deploy; treat marker/column mismatch as a stop condition; run the local apply only through the container-env command in T6 after the SELECT DATABASE() target check prints the intended database; drain auth traffic and apply/verify migration revocation before allowing new auth traffic. |
| A delayed pre-D6 refresh cookie is classified as token theft and revokes post-cutover sessions | Tag only migration-revoked rows `legacy_cutover`; return 401 and clear those cookies without kill-all, while retaining account-wide revocation for other replayed tokens; test both paths after the 10-second grace. |
| Pre-D6 access JWTs accepted on protected routes during the cutover interval | Pause ALL authenticated API traffic (not only login/refresh) from the pre-cutover drain until the new backend is verified healthy; replay a captured pre-D6 JWT against GET /auth/me in the smoke window and require 401; reopen traffic only after the smoke passes. |
| A losing within-grace refresh response erases cookies issued by a winning tab | Preserve the existing 401/no-Set-Cookie/no-kill-all race response for non-legacy revoked rows; apply winner then loser response headers to one test jar and verify the replacement session still works. |
| Quoted HR CSV fields are shifted or changed across conversion, offline validation, and live UAT | Use the shared strict CSV parser in both Node consumers; cover quoted commas, escaped quotes, embedded newlines, malformed rows, and conversion-to-consumer round trips with synthetic sentinels. |
| An approved blank end date is replaced by `TODO` and fails open-ended date checks | Exclude `effective_end_date` from TODO substitution; preserve blank/NULL as open-ended and test workbook, CSV validator, and API parity paths. |
| Backend test command exits green while DB integration tests are skipped | Require output evidence that integration tests ran; unit-only/skip mode is NOT PASS and must be rerun against the provisioned test DB. |
| UAT runs against production or unapproved HR data | Run first on staging; use HR-approved inputs stored outside the repository; never copy the workbook/CSVs into tracked templates or write case/person details to logs. |
| Third-party-site browser cookie blocked under SameSite=Lax | Record client type and origin; use same-site proxy or hold that client at a security design gate. |

## Definition of done

- D3 repository scripts and examples use cookie/CSRF transport; header-only protected requests fail; every known external client has a documented owner and migration result.
- Password create/reset/forced-change guidance and client validation match the backend's client-checkable rules; backend remains the authority for history.
- D6 confirmed TTLs are enforced by both refresh expiry and access JWT expiry; migration parity and all named tests/gates pass; forced re-login has been communicated; a delayed migration-revoked cookie cannot revoke a new session, a within-grace losing response cannot erase a winning tab's cookies, and rotated-token replay detection remains active.
- The offline validator, live UAT runner, and XLSX sync tool accept/use HR data only through explicit private paths, parse quoted CSV without data loss, preserve open-ended dates, expose only sanitized aggregates, and leave tracked synthetic templates unchanged; live UAT begins only after active staging master parity passes. Both consumers select the same area under the shared rule, including overlapping basis types; the existing TEST_SEED regression remains synthetic-only. Technical calculation tests match the current per-area/365-day backend, every approved case executes exactly once, and no zero/subset run can pass.
- DB-backed integration tests are evidenced as executed, not merely skipped with a successful unit-only exit.
- Issue #23 remains needs-info until HR/Product confirms the independently prepared calculation and area-selection contracts, HR-backed 100% UAT executes every approved case, and sign-off is complete; only then update director readiness and close the issue. If an HR rule differs from the current technical rule, stop T7 and route that change through a separate approved plan.
