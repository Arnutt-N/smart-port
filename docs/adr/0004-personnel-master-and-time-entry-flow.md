# ADR-0004: แยกมาสเตอร์บุคลากรจากโฟลเพิ่มรายการนับเวลา

- **Status**: Accepted
- **Date**: 2026-08-11
- **Domain**: `CONTEXT.md` (ข้อมูลบุคลากร, โปรไฟล์ career, ปิดใช้งานบุคลากร)

## Context

หน้า `/time-counting`, `/time-multiplier`, `/time-difference`, `/position-compare` เพิ่มรายการ/คำขอผ่านโมดอลที่มี typeahead บุคลากร แต่ค้นหาคนไม่ได้ใช้งานจริง ทำให้เกิดคำถามว่าโฟลควรเป็น “เลือกคนจากฐานก่อน แล้วค่อยเพิ่มรายการ” หรือ “ทำในโมดอลครบครั้งเดียว”

รายการเกื้อกูล / ทวีคูณ / แตกต่าง / เทียบตำแหน่งเป็นข้อมูลที่**ผูกกับบุคลากร** ไม่ใช่ที่สร้างคนใหม่ ในขณะที่ระบบยังไม่มีเมนูมาสเตอร์บุคลากร (มีแค่นำเข้า Excel และ `/profile/:id` แบบดูรายคน)

## Decision

1. **โฟลหลักของ 4 หน้าเวลานับ = ทำในโมดอลครั้งเดียว** — กดเพิ่มรายการ/ยื่นคำขอ → typeahead เลือกบุคลากร → กรอกรายการ → บันทึก
2. **โฟลรอง = เริ่มจากคน** ผ่านเมนู **ข้อมูลบุคลากร** (มาสเตอร์) และ **โปรไฟล์ career** (`/profile/:id`) — ไม่บังคับเลือกคนก่อนทุกครั้งที่กดปุ่มเพิ่มบนหน้ารายการเวลา
3. **แยกหน้าชัด:**
   - **ข้อมูลบุคลากร** = มาสเตอร์ (ค้นหา / ดู / สร้างทีละคน / แก้ไข / ปิดใช้งาน) + นำเข้า Excel ยังใช้กับชุดใหญ่
   - **โปรไฟล์ career** = มุมมอง career + ทางลัดไปหน้าโมดูลเวลา แล้วเปิดโมดอลพร้อมบุคลากรนั้น (ไม่ฝัง CRUD คนและไม่ฝังฟอร์มรายการเวลาซ้ำบนโปรไฟล์)
4. **สิทธิ์มาสเตอร์บุคลากร:** เฉพาะ `admin` / `superadmin` สร้าง·แก้ไข·ปิดใช้งานได้ — `operator` / `viewer` อ่าน/ค้นหาได้ แล้วทำงานรายการเวลาตามสิทธิ์โมดูลเดิม
5. **เลิกใช้คนด้วยการปิดใช้งาน** (`is_active = 0`) ไม่ลบแถวถาวร — ประวัติรายการเวลายังอ้างอิงได้; typeahead/ค้นหาปกติไม่โชว์คนที่ปิด
6. **สร้างคนขั้นต่ำ:** ชื่อ + สกุล + `citizen_id` (+ คำนำหน้าถ้ามี) — `citizen_id` เป็น natural key **แก้ใน UI ปกติหลังสร้างไม่ได้**
7. **typeahead ไม่พบคน:** แสดงว่าไม่พบ + (admin) ลิงก์ไปสร้างที่ข้อมูลบุคลากร — ไม่สร้างคน inline ในโมดอลรายการเวลา
8. **ลำดับทำ:** แก้ typeahead ใน 4 หน้าให้ใช้ได้ก่อน แล้วค่อยทำเมนูมาสเตอร์ + ทางลัดโปรไฟล์

## Considered Options

| ทางเลือก | ผล |
|---|---|
| บังคับเลือกคนจากรายชื่อก่อนทุกครั้ง แล้วค่อยเปิดฟอร์มรายการ | ถูกปฏิเสธเป็นโฟลหลัก — เพิ่มขั้นตอนโดยไม่จำเป็นเมื่องานเริ่มจาก “เพิ่มรายการ” |
| รวม CRUD คน + ฟอร์มรายการเวลาไว้ในโมดอล/หน้าเดียว | ถูกปฏิเสธ — คนละชั้นโดเมน สิทธิ์ต่างกัน และโมดอลหนาเกินไป |
| สร้างคนได้เฉพาะผ่านนำเข้า | ถูกปฏิเสธ — ขัดกับการแก้เคส “คนยังไม่อยู่ในระบบ” ทีละรายการ |
| Hard delete บุคลากร | ถูกปฏิเสธ — ทำลายอ้างอิงประวัติ career |

## Consequences

- 4 หน้าเวลานับยังเป็นเจ้าของโมดอลรายการ — ทางลัดจากโปรไฟล์แค่พาไปเปิดโมดอลเดิมพร้อม `personnel_id`
- ต้องมีเมนู/หน้าข้อมูลบุคลากรและ permission resource ใหม่สำหรับมาสเตอร์คน (เขียนเฉพาะ admin/superadmin)
- บั๊ก typeahead เป็น P0 แยกจากงานมาสเตอร์ — โฟลหลักพึ่งการค้นหาคนในโมดอล
- Import ยังเป็นช่องทาง batch; ไม่ถูกแทนที่ด้วยฟอร์มทีละคน
